# Отчет по практическим занятиям 7-12

Дисциплина: **Фронтенд и бэкенд разработка**  
Тема проекта: **интернет-магазин компьютерной периферии с авторизацией**

В этой части я доработал прошлый проект магазина. Теперь в нем есть регистрация, вход в систему, JWT-токены, refresh-токены, роли пользователей и разграничение прав доступа.

## Структура проекта

- `backend` - сервер на Node.js + Express.
- `frontend` - клиентская часть на React.
- `backend/app.js` - API, авторизация, роли, товары, пользователи и Swagger.
- `frontend/src/App.js` - интерфейс магазина, вход, регистрация, товары и пользователи.
- `frontend/src/api/index.js` - запросы через axios и работа с токенами.
- `frontend/src/App.scss` - стили интерфейса.

## Практическое занятие 7

Тема: **Регистрация, вход и хеширование паролей**

В этой практической нужно было добавить серверную авторизацию. Я реализовал маршруты:

- `POST /api/auth/register` - регистрация пользователя;
- `POST /api/auth/login` - вход в систему;
- `POST /api/products` - создание товара;
- `GET /api/products` - список товаров;
- `GET /api/products/:id` - товар по id;
- `PUT /api/products/:id` - обновление товара;
- `DELETE /api/products/:id` - удаление товара.

Для пользователя используются поля:

- `id`;
- `email`;
- `first_name`;
- `last_name`;
- `password`.

Пароль не хранится в открытом виде. В `backend/app.js` он хешируется с помощью библиотеки `bcrypt`, а при входе пароль сравнивается с хешем.

## Практическое занятие 8

Тема: **JWT access-токены и защищенные маршруты**

В этой практической нужно было выдавать токен при входе и добавить защищенный маршрут `GET /api/auth/me`.

После успешного входа сервер возвращает:

- `accessToken`;
- `refreshToken`;
- объект текущего пользователя.

Маршрут `GET /api/auth/me` работает только с заголовком:

```text
Authorization: Bearer <accessToken>
```

Также защищены маршруты товаров. Например, получить товар по id, изменить товар или удалить товар можно только при наличии валидного токена.

## Практическое занятие 9

Тема: **Refresh-токены**

В этой практической нужно было добавить обновление пары токенов. Я реализовал маршрут:

```text
POST /api/auth/refresh
```

Он принимает `refreshToken` и возвращает новую пару:

```json
{
  "accessToken": "...",
  "refreshToken": "..."
}
```

На сервере refresh-токены хранятся в памяти в `Set`. При обновлении старый refresh-токен удаляется, а новый добавляется. Это сделано для имитации ротации refresh-токенов.

## Практическое занятие 10

Тема: **Хранение токенов на фронтенде**

В этой практической нужно было сделать фронтенд и связать его с сервером. Я доработал React-приложение:

- сделал форму входа;
- сделал форму регистрации;
- сохраняю `accessToken` и `refreshToken` в `localStorage`;
- добавляю access-токен в каждый запрос через `axios interceptors`;
- если сервер отвечает `401`, фронтенд пробует обновить токены через `/api/auth/refresh`;
- после обновления токена исходный запрос отправляется повторно.

Файл с этой логикой находится здесь:

```text
frontend/src/api/index.js
```

После входа пользователь видит каталог товаров. Можно смотреть список товаров и открывать подробную информацию по id.

## Практическое занятие 11

Тема: **Роли пользователей и права доступа**

В этой практической нужно было добавить роли:

- гость;
- пользователь;
- продавец;
- администратор.

Я реализовал такие права:

| Маршрут | Метод | Доступ |
|---|---|---|
| `/api/auth/register` | POST | Гость |
| `/api/auth/login` | POST | Гость |
| `/api/auth/refresh` | POST | Гость |
| `/api/auth/me` | GET | Пользователь |
| `/api/users` | GET | Администратор |
| `/api/users/:id` | GET | Администратор |
| `/api/users/:id` | PUT | Администратор |
| `/api/users/:id` | DELETE | Администратор |
| `/api/products` | POST | Продавец или администратор |
| `/api/products` | GET | Пользователь |
| `/api/products/:id` | GET | Пользователь |
| `/api/products/:id` | PUT | Продавец или администратор |
| `/api/products/:id` | DELETE | Администратор |

На фронтенде права тоже учитываются:

- обычный пользователь может смотреть товары;
- продавец может добавлять и редактировать товары;
- администратор может добавлять, редактировать и удалять товары;
- администратор также может смотреть пользователей, менять им роль и блокировать их.

## Как запустить

Сначала запускается бэкенд:

```bash
cd backend
npm start
```

После этого доступны:

- API: `http://localhost:3000/api`;
- Swagger: `http://localhost:3000/api-docs`.

Потом в отдельном терминале запускается фронтенд:

```bash
cd frontend
npm run dev
```

Фронтенд лучше запускать на порту `3001`, потому что в CORS на сервере разрешен адрес:

```text
http://localhost:3001
```
